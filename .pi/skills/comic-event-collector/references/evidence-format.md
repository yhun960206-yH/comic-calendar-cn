# 证据记录与入库判定

路径：`data/collection_evidence/YYYY-MM-DD-<slug>.json`。参考 `data/collection_evidence/2026-09-25-cicf-agf.json`。记录采集 UTC 时间、每个接受活动的稳定 `event_id`、主办方公告 URL、日期/场馆佐证 URL、地址佐证 URL、极短的事实说明和版权/条款判断；对隔离项注明缺失字段或冲突。保留链接即可，不粘贴受保护的大段文案、海报或登录凭据。

## 最低门槛

- 优先主办方或具名官方渠道可直接访问且显示**本届**活动；若仅可访问正规媒体的原帖镜像，需在镜像页核对主办方署名与认证信息，并注明原站未直访；年份不得由网页发布日期或 URL 路径猜出。
- 同一活动的名称、开展首尾日期、场馆和城市相互一致。可信来源中的地址必须具体到可定位的场馆；仅有「广州市」「复兴岛」等宽泛范围时暂缓入库。
- 不得依据过往年份同名活动推断未来举办日期。源站公告写「预计」「暂定」「待定」时不能按 `confirmed` 发布；未找到可靠公告则保留证据而不入库。
- `start_date` 是首日，`end_date` 是最后一天加一日；只有官方给出具体开馆时间时才加 `start_at/end_at`，但要与日历全天逻辑及北京时区一致。
- `source_url` 放活动官方公告链接；受访问限制的官方社媒原站不得抓取，可放公开允许读取、显示认证主办方署名的原帖镜像链接并在 `attribution` 明示“主办方公告经媒体镜像，原站未直访”，提示查看最新公告。来源未明确授权的图片、描述、票价表不转载；可独立表达的短事实仍需附原始来源和使用条件判断。
- 先比对 `data/events.json` 与线上 `events.json`：同一活动仅一条稳定 UID；改期须加修订号及 UTC 观察时间，跨城市改动须先保留原城市取消记录，再用新 UID 发布新城市。活动从搜索结果消失不是取消证据。

## 交付报告

精确列出本轮搜索范围、正式新增/更新/隔离数量和证据路径；不要把某来源的总量、372 个城市订阅链接或 Skill 文件本身误称为 AI 已采集的活动数量。报告说明这是按需运行，非无人值守的 AI 定时任务。
